Git-Struktur: Arbeitsraum, .git und .gitignore

Ein Struktur-Descriptor für die Unterscheidung von Dateisystem-Besitz und Git-Verwaltung.

Grundmodell

Das Windows-Dateisystem besitzt die realen Dateien und Ordner. Git besitzt sie nicht; Git verwaltet Informationen darüber, welche Pfade und Inhalte in bestimmten Projektständen enthalten sind.

FileSystemDirectory „Organisation"
│
├── besitzt physisch: .git, .gitignore, README.md, src, bin, Notizen.txt …
│
└── enthält logisch ein GitRepository
    ├── workTree = „Organisation"
    ├── gitDir   = „Organisation\.git"
    ├── index    = Auswahl für den nächsten Commit
    └── Historie = gespeicherte frühere Projektzustände

Schematische Verzeichnisstruktur

.gitignore ist gewöhnlich eine Datei, kein Ordner. Sie ist optional und kann auch in Unterordnern vorkommen.

E:\Programmierung\Organisation\                         [Arbeitsraum / Directory]
├── .git\                                               [Git-Datenbank / Directory]
│   ├── HEAD                                             [aktueller Branch-Verweis]
│   ├── config                                           [lokale Git-Konfiguration]
│   ├── index                                            [Staging Area]
│   ├── objects\                                         [Objektdatenbank]
│   │   ├── blob                                         [gespeicherter Dateiinhalt]
│   │   ├── tree                                         [gespeicherte Verzeichnisstruktur]
│   │   └── commit                                       [gespeicherter Projektzustand]
│   ├── refs\                                            [benannte Commit-Zeiger]
│   │   ├── heads\main                                  [lokaler Branch]
│   │   ├── remotes\origin\                             [bekannte Remote-Branches]
│   │   └── tags\                                        [optionale Tags]
│   ├── logs\                                            [Reflog]
│   ├── hooks\                                           [optionale Git-Skripte]
│   └── info\                                            [lokale Zusatzinformationen]
├── .gitignore                                           [optionale Musterregeln]
├── README.md                                            [normale Datei]
├── src\                                                 [normaler Ordner]
│   ├── Programm.cs                                      [normale Datei]
│   └── .gitignore                                       [optionale, lokal geltende Musterregeln]
├── bin\                                                 [normaler Ordner]
│   └── Programm.exe                                     [normale Datei]
└── Notizen.txt                                          [normale Datei]

Die Aufzählung von .git ist ein Descriptor, keine vollständige Liste jeder technischen Datei. Je nach Git-Aktion können weitere interne Dateien und Ordner auftreten.

Verwaltungszustände einer Datei

Datei im ArbeitsordnerGit-Index.gitignore passt?Bedeutung
vorhandenneinneinUnversioniert: Git meldet sie als neue Datei.
vorhandenneinjaIgnoriert: Git blendet sie als neue Datei aus.
vorhandenjaneinVersioniert: Änderungen können für einen Commit vorgemerkt werden.
vorhandenjajaWeiterhin versioniert: Die Ignore-Regel hebt die bestehende Verfolgung nicht auf.

Eine .gitignore-Regel bedeutet: Eine bisher unversionierte passende Datei soll nicht als Kandidatin für die Aufnahme behandelt werden. Sie entfernt keine Datei rückwirkend aus Index oder Historie.

Entfernen aus Git und aus dem Arbeitsordner

git rm DateiA
→ entfernt DateiA aus dem Index und aus dem sichtbaren Arbeitsordner

git rm --cached -- DateiA
→ entfernt DateiA nur aus dem Index; die sichtbare Arbeitsdatei bleibt bestehen

Ein anschließender Commit erzeugt einen neuen Projektstand. Bereits vorhandene frühere Commits und ihre Inhalte in .git\objects bleiben davon unverändert.
